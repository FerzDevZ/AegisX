User: Apa itu OWASP Top 10?
AegisX: OWASP Top 10 adalah daftar sepuluh risiko keamanan web paling kritis yang diterbitkan Open Worldwide Application Security Project setiap beberapa tahun. Versi 2021 mencakup: A01 Broken Access Control, A02 Cryptographic Failures, A03 Injection, A04 Insecure Design, A05 Security Misconfiguration, A06 Vulnerable and Outdated Components, A07 Identification and Authentication Failures, A08 Software and Data Integrity Failures, A09 Security Logging and Monitoring Failures, dan A10 Server-Side Request Forgery. Daftar ini adalah peta jalan bagi pengembang dan penguji: kuasai satu per satu, pahami contoh serangan dan cara mencegahnya, lalu praktikkan di lab.

User: Apa itu broken access control?
AegisX: Broken access control terjadi ketika aplikasi tidak memeriksa otorisasi dengan benar, sehingga pengguna bisa mengakses fungsi atau data yang bukan haknya. Contohnya: mengganti ID di URL untuk melihat profil pengguna lain, mengakses endpoint admin langsung, memanipulasi cookie atau JWT untuk menaikkan peran, dan memanggil API langsung yang tidak dipanggil dari antarmuka. Aturan utamanya: pemeriksaan otorisasi harus dilakukan di sisi server untuk setiap permintaan, jangan pernah hanya menyembunyikan tombol di antarmuka. Saat menguji, ubah parameter seperti ID, peran, dan metode HTTP, serta coba akses endpoint yang tidak muncul di UI.

User: Apa itu Insecure Design?
AegisX: Insecure Design adalah kategori kerentanan yang berasal dari keputusan desain yang salah, bukan dari bug implementasi. Contohnya: tidak ada batasan biaya pada fitur, sehingga biaya bisa dimanipulasi; urutan langkah bisnis yang bisa dilewati; proses yang bisa diduplikasi tanpa batas; dan keputusan kepercayaan yang salah seperti mempercayai input dari klien. Ini lebih sulit diperbaiki karena butuh perubahan desain, bukan sekadar patch. Pengujinya harus berpikir seperti penyerang bisnis: apa yang bisa saya lakukan dengan logika aplikasi yang seharusnya tidak diizinkan? Temuan seperti manipulasi harga, melewati pembayaran, atau memakai fitur tanpa membayar termasuk kategori ini.

User: Apa itu cryptographic failure?
AegisX: Cryptographic failures terjadi ketika data sensitif tidak dilindungi dengan kriptografi yang benar. Contohnya: password disimpan sebagai plaintext atau hash tanpa salt, data kartu kredit dikirim tanpa TLS, kunci enkripsi disimpan di dalam kode, atau menggunakan algoritma yang sudah usang seperti MD5 dan SHA1 untuk password. Prinsip dasarnya: jangan pernah menulis kriptografi sendiri, gunakan library yang teruji, hash password dengan algoritma lambat seperti bcrypt atau argon2 dengan salt unik, enkripsi data sensitif saat diam dan saat bergerak, dan kelola kunci secara terpisah dari kode. Uji dengan mencari data sensitif yang terpapar di respons, log, atau penyimpanan.

User: Apa itu security misconfiguration?
AegisX: Security misconfiguration adalah kerentanan karena pengaturan yang salah atau default yang tidak aman. Contoh umum: direktori yang bisa dijelajahi, pesan error yang membocorkan stack trace, header keamanan yang hilang seperti CSP dan X-Frame-Options, akun default yang belum diganti, debug mode aktif di produksi, dan izin file yang terlalu longgar. Serangan yang sering terjadi adalah memanfaatkan default credentials, melihat file backup atau file konfigurasi yang terpapar, dan mengakses panel admin yang tidak dilindungi. Pemeriksaan manual penting karena scanner otomatis sering melewatkan masalah konfigurasi. Cek juga file seperti .git, .env, dan backup yang mungkin terpapar.

User: Apa itu vulnerable and outdated components?
AegisX: Vulnerable and outdated components terjadi ketika aplikasi menggunakan library, framework, atau sistem dengan kerentanan yang sudah diketahui dan sudah ada patch-nya. Contoh terkenal: Log4Shell di Log4j (CVE-2021-44228), Apache Struts pada kasus Equifax, dan komponen JavaScript dengan kerentanan RCE. Karena komponen adalah bagian kode yang paling sering dipakai, kerentanan di dalamnya berdampak luas dan mudah dieksploitasi. Pencegahannya: buat inventaris semua komponen, pantau sumber informasi kerentanan seperti NVD, perbarui secara rutin, dan gunakan software composition analysis. Saat menguji, cek versi library di header, file, atau fingerprinting, lalu cocokkan dengan database kerentanan.

User: Apa itu identification and authentication failures?
AegisX: Identification and authentication failures mencakup masalah pada proses login dan manajemen sesi. Contohnya: membiarkan brute force tanpa batasan percobaan, tidak menerapkan kebijakan password yang wajar, session ID yang bisa ditebak atau tidak dirotasi setelah login, logout yang tidak menghancurkan sesi, dan fungsi reset password yang rentan. Pengujinya harus mencoba: brute force login, session fixation, menebak token reset, dan melihat apakah session masih valid setelah logout. Pertahannya: rate limiting, multi-factor authentication, session ID acak yang dirotasi, dan masa berlaku sesi yang pendek untuk aktivitas sensitif.

User: Apa itu software and data integrity failures?
AegisX: Software and data integrity failures terjadi ketika kode atau data tidak dilindungi dari modifikasi tidak sah. Contohnya: update otomatis yang tidak diverifikasi tanda tangannya, dependency yang diambil tanpa memeriksa checksum, data deserialized dari sumber tidak tepercaya, dan pipeline CI/CD yang tidak aman sehingga kode jahat bisa masuk. Serangan supply chain terkenal termasuk kompromi library populer untuk menyuntikkan backdoor. Pencegahannya: verifikasi tanda tangan digital pada update, gunakan lockfile dan verifikasi checksum dependency, hindari deserialisasi data tidak tepercaya, dan amankan pipeline rilis dengan review dan kontrol akses.

User: Apa itu security logging and monitoring failures?
AegisX: Security logging and monitoring failures terjadi ketika aktivitas penting tidak dicatat atau tidak dipantau, sehingga serangan tidak terdeteksi. Contohnya: tidak ada log untuk percobaan login gagal, log dihapus atau disimpan terlalu singkat, tidak ada alert untuk aktivitas mencurigakan, dan log tidak dilindungi dari manipulasi. Tanpa log yang baik, organisasi tidak bisa mendeteksi kebocoran data yang sudah berlangsung berbulan-bulan. Pencegahannya: catat login berhasil dan gagal, perubahan hak akses, akses data sensitif, dan kesalahan aplikasi; kirim log ke sistem terpusat yang dilindungi; dan buat alert untuk pola mencurigakan. Saat menguji, periksa apakah aktivitas Anda tercatat atau justru tidak ada log sama sekali.

User: Apa itu race condition?
AegisX: Race condition terjadi ketika dua operasi berjalan bersamaan dan aplikasi tidak menangani konkurensi dengan benar, sehingga hasilnya tidak seperti yang diharapkan. Contoh klasik di dunia bug bounty: kupon diskon yang bisa dipakai berulang kali dengan mengirim banyak permintaan bersamaan, saldo yang bisa ditarik dua kali sebelum berkurang, atau vote yang bisa dihitung dua kali. Pengujinya bisa menggunakan teknik seperti mengirim ratusan permintaan paralel ke endpoint yang sama dengan Burp Intruder, atau menggunakan tools khusus race condition. Pencegahannya: transaksi database, kunci pada operasi sensitif, dan verifikasi ulang kondisi sebelum eksekusi. Ini termasuk bug favorit karena dampaknya sering langsung terlihat.

User: Apa itu insecure deserialization?
AegisX: Insecure deserialization terjadi ketika aplikasi menerima data serialized dari sumber tidak tepercaya dan memprosesnya tanpa validasi, sehingga penyerang bisa mengontrol perilaku aplikasi. Contohnya: cookie Java yang berisi objek serialized, atau data pickle di Python. Penyerang bisa membuat payload yang mengeksekusi perintah saat data dibuka. Dampaknya bisa dari serangan denial of service hingga remote code execution. Pencegahannya: jangan menerima data serialized dari sumber tidak tepercaya, gunakan format data sederhana seperti JSON yang tidak membawa kode, dan validasi serta batasi kelas yang boleh di-deserialize. Saat menguji, perhatikan parameter yang nilainya tampak seperti data serialized terenkripsi atau encoded.

User: Apa itu mass assignment?
AegisX: Mass assignment adalah kerentanan yang terjadi ketika framework secara otomatis mengikat parameter dari permintaan ke properti objek tanpa memfilter mana yang boleh diubah pengguna. Contohnya: aplikasi punya form edit profil dengan field nama dan email, tetapi endpoint menerima semua parameter, sehingga penyerang menambahkan parameter isAdmin=true atau role=admin pada permintaan dan perannya berubah. Framework seperti Rails, Laravel, dan Django punya mekanisme ini. Pencegahannya: gunakan allowlist field yang boleh diubah, atau binding manual, dan jangan pernah langsung mengikat seluruh permintaan ke objek model. Saat menguji, coba tambahkan parameter tersembunyi seperti role, isAdmin, atau balance ke setiap permintaan yang mengubah data.

User: Apa itu path traversal?
AegisX: Path traversal adalah kerentanan yang memungkinkan penyerang membaca file di luar direktori yang seharusnya, misalnya dengan memanfaatkan parameter nama file. Contoh payload: ../../../../etc/passwd atau varian encoded seperti %2e%2e%2f dan ....//. Dampaknya bisa membaca file konfigurasi, source code, atau data sensitif. Pencegahannya: validasi nama file dengan allowlist, gunakan fungsi yang membatasi akses ke direktori tertentu, dan jangan membangun path dari input pengguna secara langsung. Saat menguji, coba berbagai encoding dan kombinasi traversal di setiap parameter yang memuat nama file atau path, lalu lihat apakah isi file muncul dalam respons.

User: Apa itu request smuggling?
AegisX: HTTP request smuggling adalah teknik memanfaatkan perbedaan cara server front-end dan back-end memproses batas permintaan HTTP, sehingga penyerang bisa menyelundupkan permintaan kedua yang tidak terlihat. Terjadi karena ketidakcocokan Content-Length dan Transfer-Encoding. Dampaknya bisa berupa mem-bypass kontrol akses, meracuni cache, atau membajak permintaan pengguna lain. Ini adalah teknik tingkat lanjut yang perlu dipahami dengan baik. Pencegahannya: pastikan server dan proxy menggunakan cara yang sama dalam memproses header, nonaktifkan Transfer-Encoding di front-end jika tidak perlu, dan gunakan HTTP/2 yang lebih aman. Saat menguji, fokus pada konfigurasi yang mencampur server dengan perilaku berbeda.
