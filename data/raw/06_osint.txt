Open Source Intelligence, or OSINT, is the collection and analysis of publicly available information. OSINT is the foundation of reconnaissance because it is passive, legal, and surprisingly revealing. Companies leak enormous amounts of information through their own public channels without realizing it. A skilled OSINT analyst can map an organization's infrastructure, employees, and habits without sending a single packet to their servers.

Search engines are the first OSINT tool. Google dorks are search queries that target specific types of content. The site: operator limits results to one domain, like site:example.com filetype:pdf to find PDF documents. The inurl: operator searches for keywords in URLs, like inurl:admin to find admin panels. The intitle: operator finds pages with keywords in their titles. Common dork targets include exposed login pages, configuration files, backup archives, database dumps, and internal documents. Search operators work on Google, Bing, and specialized engines like Shodan.

Shodan is a search engine for internet-connected devices. Unlike Google, which indexes web pages, Shodan indexes device banners: the responses services send when probed. Search for a port with port:22, a service with product:nginx, or a country with country:ID. Shodan reveals exposed databases, industrial control systems, webcams, and misconfigured services that would never appear in a regular search. Organizations can search their own IP ranges on Shodan to find exposed devices before attackers do.

Censys and ZoomEye provide similar device search functionality to Shodan with different coverage. The value of device search engines in reconnaissance is finding assets the organization forgot about: a development server exposed to the internet, an old printer with default credentials, or a database listening on a public IP. Every device found expands the attack surface.

Certificate transparency logs are a goldmine for subdomain discovery. When a certificate authority issues an SSL certificate for a domain, the certificate is publicly logged. Services like crt.sh let anyone search those logs. Searching for the domain example.com returns every certificate ever issued for it, and each certificate lists the domains it covers. Attackers and defenders use these logs to find subdomains that are not linked anywhere else. Subdomain enumeration through certificate transparency is passive and highly effective.

Whois records contain registration information for domains. A whois lookup reveals the registrar, creation date, expiration date, and sometimes the registrant's name, organization, and contact details. Privacy protection services hide individual registrants, but the organization itself is usually visible. Comparing registration data across an organization's domains reveals patterns: the same registrar, the same nameservers, or the same administrative contact tie domains together. DNS history services show past IP addresses and records, which can reveal infrastructure that still points at old providers.

DNS itself leaks information. Zone transfers request every record from a DNS server, and misconfigured servers answer. The dig command performs a zone transfer with dig AXFR example.com. While rare today, it is always worth trying. Passive DNS services record historical DNS resolutions, showing which hostnames resolved to which IPs over time. This history reveals the infrastructure behind a domain even after the records change.

Email addresses are a trail of breadcrumbs. Corporate email addresses follow patterns like firstname.lastname@example.com or flastname@example.com. Search engines and data breach repositories confirm those patterns. Once the pattern is known, you can predict other employees' addresses. Services that verify email deliverability confirm whether guessed addresses exist. Breach notification services like HaveIBeenPwned tell users which of their accounts appeared in data breaches, and security researchers use breach data to understand credential reuse across an organization.

Social media profiles reveal organizational structure. LinkedIn shows job titles, roles, and team composition. An analyst maps the technology stack from job postings: if the company is hiring for Kubernetes administrators, they likely run Kubernetes. GitHub profiles of employees reveal personal projects, which often contain work-related code, API keys, and internal tooling. Accidental commits of credentials to public repositories happen constantly, and scanning GitHub for company domains or employee usernames finds them.

Geolocation and metadata analysis extract information from files and photos. EXIF data in images records the GPS coordinates and device information of where the photo was taken. Photographs of office buildings, server rooms, or employees at work reveal physical locations. Document metadata records the author, software, and sometimes the full file path of the original document, exposing internal naming conventions and usernames. Services that strip metadata are essential for organizations that publish documents.

The OSINT process ends with correlation. Individual data points seem harmless, but combined they paint a complete picture. An employee's email address links to a personal GitHub, which contains a work project, which reveals internal tool names, which appear in job postings, which indicate the technology stack, which guides the technical reconnaissance. OSINT is not a single search; it is a discipline of connecting fragments into intelligence. Defenders practice OSINT on their own organization to see what attackers see, then close the gaps.
