Cryptography protects data through mathematics. Understanding the basics of encryption, hashing, and digital signatures is essential for both attackers and defenders. Cryptographic failures appear constantly in penetration tests: weak algorithms, short keys, reused nonces, and broken implementations. A tester who recognizes cryptography failures finds serious vulnerabilities that scanners miss.

Encryption transforms readable plaintext into unreadable ciphertext. Symmetric encryption uses one key for both encryption and decryption. AES is the standard symmetric algorithm, used in variants like AES-128, AES-192, and AES-256, where the number indicates the key size in bits. Asymmetric encryption uses a key pair: a public key for encryption and a private key for decryption. RSA and elliptic curve cryptography are the common asymmetric systems. Asymmetric encryption is slower than symmetric, so real systems use asymmetric encryption to exchange a symmetric session key, then switch to symmetric encryption for the data.

Hashing is different from encryption. A hash function produces a fixed-size output from any input, and the process is one-way: you cannot recover the input from the hash. SHA-256 is the standard hash function. Hashing verifies integrity: if the data changes, the hash changes. Passwords are stored as hashes rather than plaintext, so a database breach does not directly reveal passwords. Storing a plain hash is still weak because attackers precompute hashes of common passwords in rainbow tables. The solution is salting: adding a random value to each password before hashing, so identical passwords produce different hashes. Use dedicated password hashing functions like bcrypt, scrypt, or Argon2 that are deliberately slow.

TLS secures communication on the internet. When a browser connects to a site over HTTPS, the server presents a certificate that proves its identity. The certificate is issued by a certificate authority, which vouches that the public key belongs to the named organization. The browser verifies the certificate chain back to a trusted root authority. TLS failures in applications include expired certificates, certificates for the wrong domain, and clients that skip certificate verification entirely. Applications that disable certificate validation accept any server and leak all traffic to anyone who intercepts it.

Network security operates in layers. The network layer routes packets between hosts, where firewalls filter traffic by IP address and port. The transport layer carries connections, where stateful firewalls track connection state. The application layer carries the actual data, where web application firewalls inspect requests for attacks. Defense in depth places controls at every layer, because an attacker who bypasses one layer meets the next. A firewall that blocks all inbound ports except 80 and 443 forces attackers to attack the web application, where the next layer of controls waits.

Segmentation divides the network into zones with different trust levels. The demilitarized zone, or DMZ, holds public-facing servers and sits between the internet and the internal network. Internal networks hold workstations and servers, further divided into segments for different departments or sensitivity levels. A database containing customer data belongs in its own segment with strict access rules. Segmentation limits the blast radius: a compromised web server in the DMZ should not automatically reach the database segment. Testing segmentation is a common engagement goal: verify that a foothold in one zone cannot reach another.

Wireless networks have their own security model. WPA2 and WPA3 protect Wi-Fi with encryption and authentication. WPA2 uses a pre-shared key, and weak passphrases are vulnerable to offline dictionary attacks: capture the four-way handshake, then crack the passphrase locally. WPA3 improves on WPA2 with stronger key exchange, but enterprise networks use 802.1X with individual credentials instead of a shared password. Rogue access points imitate legitimate networks to capture credentials, and evil twin attacks broadcast the same network name to trick devices into connecting. Wireless testing verifies encryption strength, detects rogue access points, and validates network separation between guest and corporate networks.

Remote access technology expands the attack surface. VPN concentrators, remote desktop gateways, and SSH servers all face the internet and invite attack. Default credentials, outdated software, and missing multi-factor authentication are common remote access findings. Brute force attacks target SSH and remote desktop with password lists. Fail2ban and similar tools block repeated failed attempts. The most effective defense for remote access is multi-factor authentication combined with network-level restrictions that limit which source addresses can connect.

Cloud security moves traditional controls to a shared responsibility model. The cloud provider secures the infrastructure; the customer secures everything they configure: identity, access, data, and network settings. Misconfigured cloud storage is one of the most common data breaches: a storage bucket set to public exposes every object it holds. Identity and access management controls who can do what, and overly permissive roles cause privilege escalation. Cloud penetration testing focuses on identity misconfigurations, exposed storage, and overly broad permissions, all of which are reachable through the management console as well as the application.
