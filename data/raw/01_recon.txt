Reconnaissance is the first phase of any penetration test. The goal is to gather as much information about the target as possible before attacking it. Good recon saves time later because you only test services that actually exist.

Passive reconnaissance means collecting information without touching the target directly. Search engines, certificate transparency logs, DNS records, and public code repositories are all passive sources. Certificate transparency logs are especially useful because they reveal subdomains that are not linked from the main site. Search for the target domain in crt.sh to find every certificate ever issued, then extract the subdomains from those certificates.

Active reconnaissance means sending packets to the target. DNS enumeration, port scanning, and service fingerprinting are active techniques. Always obtain written authorization before running active scans against systems you do not own. Scanning without permission is illegal in most jurisdictions.

DNS enumeration starts with a simple zone transfer attempt. If the server allows AXFR, you get every record at once. Most servers block zone transfers now, so you usually need brute force instead. Use a wordlist of common subdomains like www, mail, ftp, admin, dev, staging, api, vpn, and backup. The more specific the wordlist, the better the results. Combine DNS brute forcing with certificate transparency to maximize subdomain coverage.

Port scanning identifies which services are listening on a host. The most common tool is nmap. A basic TCP connect scan checks every port on a host and reports which ones are open. The default nmap scan is fast but noisy. A SYN scan is stealthier because it never completes the TCP handshake, but it requires root privileges. UDP scans are slow because UDP is connectionless and hosts rarely respond to closed UDP ports, so timeouts dominate.

Start broad and narrow down. Scan all 65535 TCP ports on the target, then focus on the services you find. A full port scan takes time, so prioritize. Web servers usually run on ports 80 and 443. SSH runs on 22. Remote desktop on 3389. Databases like MySQL and PostgreSQL run on 3306 and 5432. After finding open ports, fingerprint the exact service version with nmap version detection, because knowing the version tells you which known vulnerabilities might apply.

Service version detection is critical for vulnerability assessment. The banner that a service returns often reveals the exact software and version. nmap can grab banners automatically and match them against a database of known services. If you find an outdated version of a web server, an SSH daemon, or a database, research that version for published vulnerabilities. A single outdated service can be the entry point into the whole network.

The reconnaissance phase ends with a complete inventory. Write down every hostname, IP address, open port, service, and version you found. This inventory drives the next phase: vulnerability analysis. Without a complete inventory you will miss attack surface, and missing attack surface means missing findings.

Subdomain enumeration is one of the highest-value recon activities in bug bounty. Many companies protect their main domain carefully but forget about their staging or internal subdomains. A forgotten staging server often runs older software with known vulnerabilities. When you find a new subdomain, resolve it to an IP address and add it to your scan targets. Also check for dangling DNS records where a subdomain points to an expired third-party service; taking over that subdomain is often a valid bug bounty finding.

Content discovery is the final piece of recon. Tools like ffuf and gobuster brute force directories and files on a web server using wordlists. Look for admin panels, backup files, configuration files, source maps, and API documentation. Backup files like config.php.bak or .env can contain credentials. Source maps reveal the original source code of JavaScript applications. API documentation tells you exactly which endpoints exist and what parameters they expect. Every discovered file expands the attack surface.

Remember the reconnaissance golden rule: never attack a target you are not authorized to test. In bug bounty, read the program scope carefully. Some programs only allow testing certain subdomains and prohibit scanning infrastructure providers. Stay within scope, follow the rules of engagement, and stop when you find enough evidence to write a report. Responsible disclosure protects you legally and keeps the program healthy.
