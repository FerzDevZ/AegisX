User: How do I enumerate subdomains?
AegisX: Start with passive sources: certificate transparency logs via crt.sh, search engines, and DNS records collected by services like SecurityTrails. Then brute force subdomains with a wordlist using a tool like ffuf or gobuster. After collecting candidate names, resolve them with DNS and keep only live hosts. Compare resolved IPs to spot subdomains on unusual infrastructure or cloud providers, which are often interesting targets. Finally, fingerprint each live host with a tool like httpx to identify web servers and applications. Keep everything organized in a file because later stages build on the full asset list.

User: How do I do a port scan with nmap?
AegisX: Begin with host discovery to find live hosts, then scan for open ports. A full TCP scan across all 65535 ports is slow, so start with common ports: nmap -sV -p 80,443,22,3306,5432 target. Use -sS for a SYN scan when you have the privilege, and -sV to fingerprint service versions, because versions tell you which known vulnerabilities may apply. Use -sC for default scripts to gather more detail, and -O for OS detection when permitted. For UDP services, scan selectively because UDP scanning is slow and unreliable. Always respect scope: scanning outside the allowed range violates program rules and may be illegal.

User: What is the difference between active and passive reconnaissance?
AegisX: Passive reconnaissance collects information without touching the target directly. You rely on third-party sources: certificate transparency logs, search engines, DNS records, archived pages, and public code repositories. Because you never send traffic to the target, it leaves no trace and is almost always safe within scope. Active reconnaissance sends requests to the target: port scans, banner grabbing, and directory brute forcing. It produces richer, more current data but is detectable and requires explicit permission. In a structured engagement, do passive recon first to build a target list, then move to active techniques against the assets that are in scope.

User: How do I use ffuf for directory and content discovery?
AegisX: Ffuf is a fast web fuzzer. For directory discovery: ffuf -w wordlist.txt -u https://target.com/FUZZ, where FUZZ is the placeholder ffuf replaces with each wordlist entry. Filter noise by status code with -mc 200,204,301 and by size with -fs to hide default responses. For parameter discovery, fuzz the query string: ffuf -w params.txt -u https://target.com/page?FUZZ=1. Use a quality wordlist like SecLists for better results, and increase speed carefully with -t threads while respecting the target. Confirm each interesting result manually before reporting.

User: What is Burp Suite and how do I use it for web testing?
AegisX: Burp Suite is the standard proxy for manual web application testing. Its core function is intercepting HTTP traffic between your browser and the target, letting you inspect and modify every request. The workflow: set your browser to use Burp as proxy, browse the application so Burp records history, then send interesting requests to Repeater to modify and resend them manually. Intruder automates customized attacks like brute forcing parameters, and the scanner automates vulnerability detection on paid editions. Learn the proxy, history, and Repeater first; they cover most manual testing needs. The free Community edition is enough to learn and test many applications.

User: What is Shodan and how is it used in reconnaissance?
AegisX: Shodan is a search engine for internet-connected devices. Unlike Google, which indexes web pages, Shodan scans the internet and indexes banners from services like SSH, HTTP, and databases, along with metadata such as open ports, software versions, and geographic location. In reconnaissance, search your target's IP ranges to see exposed services: search:net:203.0.113.0/24, or search for specific software with product:nginx and country filters. It is valuable for finding forgotten assets, exposed databases, and default installations before you send a single packet. Be careful: what Shodan shows is public data, but testing those services still requires scope and permission.

User: What is the role of wordlists in penetration testing?
AegisX: Wordlists are files of candidate values used in brute forcing and fuzzing: subdomain names, directory names, usernames, passwords, and parameter names. Their quality often determines whether brute force succeeds. SecLists is the standard collection, organized by purpose, with directories like Discovery and Passwords. RockYou is a famous password list from a real breach. Choose a wordlist appropriate to the task: small targeted lists for speed, large ones for coverage. Combine tools with lists: ffuf needs a directory wordlist, hydra needs usernames and passwords, and john the ripper cracks hashes with password lists and rules that mutate them.

User: How do I find hidden parameters in a web application?
AegisX: Hidden parameters can change application behavior and are often unprotected. Start by reading the application's JavaScript files and looking for parameter names in API calls. Fuzz common parameter names on every endpoint: ffuf or Burp Intruder with a parameter wordlist, then compare response lengths and status codes for anomalies. Look for parameters like debug, admin, test, and verbose that may enable hidden features. Check how the server treats unexpected parameters: some frameworks reflect them, some log them, some act on them. When a parameter changes the response meaningfully, investigate what it controls and whether it bypasses access control.

User: What is OSINT and what sources do you use?
AegisX: OSINT or Open Source Intelligence collects information from public sources. Common sources: search engines with advanced operators, certificate transparency logs, DNS records, WHOIS data, social media, GitHub for leaked credentials or internal code, paste sites for exposed data, and archived versions of websites. For a specific person, look at social profiles, public posts, and metadata in shared files. For an organization, map domains, subdomains, employees, and technology from job posts and error pages. Organize findings by entity and keep the source with each fact, because provenance matters for legal and report purposes. OSINT is usually passive and low risk, but the information should never be used outside an authorized engagement.

User: What is certificate transparency and why is it useful?
AegisX: Certificate transparency is a public logging system where every TLS certificate issued by a CA must be recorded, so misissued certificates can be detected. Because the logs are public and searchable, they become a goldmine for reconnaissance: every certificate ever issued for a domain reveals its subdomains, including ones not linked anywhere else. crt.sh queries the logs: search for %.example.com to list all certificates for the domain. This often finds staging servers, internal tools, and forgotten subdomains that make excellent test targets. Combine certificate data with DNS resolution to filter live hosts before deeper testing.

User: How do I use curl to test web endpoints manually?
AegisX: Curl gives you full control over HTTP requests from the terminal. Basic form: curl https://target.com/path. Add -i to see response headers, -X POST to change the method, -d 'key=value' to send a body, and -H 'Header: value' to set custom headers. Use -b to send a cookie jar and -c to save cookies from a login. Follow redirects with -L, and use -o /dev/null -w '%{http_code}' to see just the status code. For JSON APIs, send -H 'Content-Type: application/json' -d '{"key": "value"}'. Curl is ideal for scripting repeated tests and for sending exact requests that proxies would alter.

User: What is the difference between crawling and fuzzing?
AegisX: Crawling discovers content by following links, like a search engine spider: it starts at a URL, reads the page, and follows every link it finds. Fuzzing guesses content by sending many inputs: it tries every word in a list against a placeholder, like guessing directory names or parameter values. Crawling finds what the application links to; fuzzing finds what exists but is not linked, which is often more interesting because hidden pages may lack protection. Use both: crawl to map the application you know about, then fuzz to discover the parts the developers did not intend you to find. Compare results and manually review anything fuzzing surfaces.

User: What is subdomain takeover and how do I detect it?
AegisX: Subdomain takeover happens when a subdomain points to an external service, such as GitHub Pages, Heroku, or a cloud bucket, that is no longer claimed, so an attacker can claim it and control the subdomain's content. To detect it, enumerate subdomains, resolve their CNAME records, and look for CNAMEs pointing to external providers. Then check whether the provider returns an unclaimed page like a 404 or an account-not-found message. If the service allows claiming the name and the page is unclaimed, the subdomain may be takeable. Confirm by registering the name only when the program allows it; otherwise report the evidence. Fixes: remove dangling DNS records and monitor for unclaimed CNAMEs.

User: How do I check HTTP security headers?
AegisX: Send a request and inspect the response headers. Content-Security-Policy controls which resources the browser may load and is the main defense against XSS. X-Frame-Options or CSP frame-ancestors prevents clickjacking. Strict-Transport-Security forces HTTPS and stops protocol downgrade. X-Content-Type-Options: nosniff stops MIME sniffing. Referrer-Policy limits what the referrer header leaks. Permissions-Policy restricts browser features. Missing headers are usually low-severity findings, but combined they reduce the defense in depth. Report which headers are missing, why they matter for this application, and the exact header values to set.

User: What is GitHub recon and what do you look for?
AegisX: GitHub stores more than code: developers accidentally commit secrets, internal paths, and configuration that should stay private. Search for the organization name and domain in code: searching for "example.com" may reveal internal endpoints, and searching for filenames like .env or config files may find leaked keys. Use GitHub's code search with filters like org:name and extension:env. Look for API keys, tokens, database connection strings, and internal URLs in comments and documentation. If you find a live secret, report it through the proper channel and do not use it. Public repositories are fair game for OSINT, but any secret found must be handled responsibly.

User: What is the difference between a vulnerability scanner and manual testing?
AegisX: A vulnerability scanner automates checks for known issues by sending thousands of requests and matching responses against signatures, so it covers a lot of ground quickly and finds common problems like missing headers and known CVEs. Manual testing uses human reasoning to understand the application's logic and find issues scanners miss: business logic flaws, complex authorization chains, and creative abuse of features. Scanners produce false positives and miss anything requiring context. In practice, use scanners for breadth and manual testing for depth. A tester who reads the application's behavior like a story finds the vulnerabilities that matter most, which is why the best programs combine both.

User: How do I use gobuster for content discovery?
AegisX: Gobuster brute forces directories, files, and DNS names. For directories: gobuster dir -u https://target.com -w wordlist.txt. Use -x php,html to also try extensions and -s '200,204,301,302' to show only interesting status codes. For subdomains: gobuster dns -d example.com -w subdomains.txt, using the domain's DNS server. Gobuster is simple and reliable; ffuf is faster and more flexible for the same job. Whatever tool you use, filter results by status and size to remove the default page noise, and manually verify every hit before including it in your report or testing it further.

User: What is Wayback Machine and how do you use it in recon?
AegisX: The Wayback Machine archives snapshots of websites over time. In reconnaissance, it reveals what a site looked like and what endpoints existed before, including pages that have since been removed or hidden. The CDX API lets you list archived URLs for a domain: https://web.archive.org/cdx/search/cdx?url=example.com/*&output=json. From that list, look for interesting paths like admin panels, old API versions, and files that may still be live on the server. Archive data also shows how the application changed, which can reveal deprecated features still accessible. Wayback is passive and safe: you are querying an archive, not the target itself.

User: How do I use httpx for probing hosts?
AegisX: Httpx probes a list of hosts and reports which ones respond and what they run. Give it a list of subdomains or IPs: cat hosts.txt | httpx. It follows redirects by default and reports the final URL, status code, title, and detected technologies. Use flags like -mc 200 to filter by status, -title to show page titles, -tech-detect to identify frameworks, and -web-server to show the server software. It is the standard step between DNS resolution and deeper testing: after enumerating hundreds of subdomains, httpx reduces them to the handful running web applications worth investigating.
