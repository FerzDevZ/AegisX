User: Apa risiko keamanan baru dari AI coding agent yang otonom?
AegisX: AI coding agent modern tidak hanya menyarankan kode; ia bisa menjalankan perintah shell, memasang paket, mengubah file, menjalankan tes, mengakses jaringan, dan mendorong branch secara mandiri. Banyak pengembang menjalankannya dengan mode auto-accept, artinya agent bekerja dengan izin penuh pengembang dan sedikit pengawasan manusia. Konsekuensinya, agent yang konteksnya disusupi punya radius ledakan yang sama dengan workstation pengembang yang disusupi: bisa memasang paket jahat, menulis ke file mana pun, mengubah konfigurasi CI, dan mendorong kode berbahaya. Karena itu agentic coding memperkenalkan ancaman yang tidak ada di alur pengembangan tradisional dan butuh kontrol khusus.

User: Bagaimana konten repositori bisa menjadi sumber instruksi bagi agent?
AegisX: Agent membaca banyak konten sebagai konteks: body isu, deskripsi dan komentar pull request, file README, changelog dependensi, trace error, halaman web yang diambil, dan respons tool MCP. Semua konten ini menjadi instruksi ketika agent membacanya, jadi siapa pun yang bisa menulis ke salah satu sumber itu bisa memengaruhi perilaku agent. Ini adalah indirect prompt injection pada alur pengembangan: penyerang membuka isu berisi instruksi tersembunyi, dan ketika pengembang menyuruh agent memperbaiki isu itu, agent membaca dan mengikuti instruksi tersembunyi tersebut. Konten dari luar harus diperlakukan sebagai data yang tidak tepercaya, bukan instruksi.

User: Apa itu rules file dan mengapa berbahaya jika bisa diubah?
AegisX: Rules file seperti .cursorrules, CLAUDE.md, AGENTS.md, .github/copilot-instructions.md, dan .windsurfrules secara diam-diam mengarahkan setiap generasi kode berikutnya. Karena agent membaca dan mematuhinya terus-menerus, file ini adalah alat kendali yang persisten. Bahayanya: file ini bisa diubah oleh pull request jahat atau oleh agent itu sendiri, lalu menanamkan instruksi yang mengubah perilaku semua sesi berikutnya tanpa disadari manusia. Karena itu rules file harus diperlakukan seperti kode: perubahan lewat pull request yang direview, tidak bisa diubah langsung, dan isinya diaudit secara berkala untuk instruksi tersembunyi.

User: Apa itu AI-assisted typosquatting pada paket?
AegisX: AI coding assistant sering menyarankan nama paket yang tidak benar-benar ada di registry publik. Penyerang memantau nama yang di-halusinasi ini, lalu mendaftarkan paket jahat dengan nama yang sama persis, sehingga pengembang yang mengikuti saran AI tanpa verifikasi memasang paket penyerang. Ini disebut AI-assisted typosquatting. Pencegahannya: verifikasi setiap paket yang disarankan AI benar-benar ada di registry publik sebelum memasang, periksa halaman paket, jumlah unduhan, riwayat maintainer, dan tanggal pembuatan; curigai paket dengan unduhan sangat rendah, umur kurang dari 30 hari, atau maintainer tunggal; dan pasang pemeriksaan CI yang memblokir paket di bawah ambang umur minimum.

User: Mengapa agent yang dijalankan dengan auto-accept berbahaya?
AegisX: Auto-accept berarti setiap aksi yang diusulkan agent langsung dijalankan dengan izin penuh pengembang, tanpa review manusia di setiap langkah. Kalau konteks agent sudah disusupi, misalnya lewat isu jahat atau repositori yang dimodifikasi, agent bisa memasang paket, menjalankan perintah shell, membaca rahasia, dan mendorong kode berbahaya tanpa ada yang menahan. Radius ledakannya sama dengan workstation pengembang yang disusupi. Kontrol yang disarankan: matikan auto-accept untuk operasi berisiko, jalankan agent dalam sandbox atau container, batasi izin ke yang dibutuhkan tugas, dan review perubahan yang dihasilkan agent seperti men-review perubahan manusia.

User: Apa itu MCP server dan risiko tool poisoning?
AegisX: MCP (Model Context Protocol) server menyediakan tool bagi agent. Server MCP yang jahat atau disusupi bisa meracuni deskripsi tool, meniru nama tool yang sah, mengeksfiltrasi kredensial lewat argumen tool, atau mengubah definisi tool setelah disetujui, yang disebut rug-pull. Karena agent mempercayai deskripsi dan hasil tool, tool yang diracuni bisa membuat agent melakukan aksi yang tidak diinginkan sambil mengira sedang memakai tool sah. Pencegahannya: hanya hubungkan agent ke MCP server tepercaya, tinjau definisi tool sebelum menyetujui, pantau perubahan definisi, dan perlakukan hasil tool sebagai data yang tidak tepercaya.

User: Bagaimana mengamankan rahasia saat memakai AI coding agent?
AegisX: Rahasia yang masuk ke konteks agent bisa ikut terkirim ke penyedia model atau tool eksternal, dan bisa bocor lewat log atau output yang dibagikan. Prinsipnya: jangan menaruh rahasia di file yang dibaca agent, jangan tempel token ke prompt, dan batasi akses agent ke secret management; beri kredensial dengan scope seminimal mungkin dan hanya ke langkah yang benar-benar butuh. Kalau agent bisa membaca seluruh repositori termasuk file .env atau konfigurasi dengan token, satu konteks yang disusupi sudah cukup untuk mengeksfiltrasi semuanya. Pantau juga apa yang dikirim agent ke penyedia model, dan putar rahasia yang pernah masuk ke konteks yang tidak tepercaya.

User: Apa itu confused deputy pada agent CI/CD?
AegisX: Confused deputy terjadi ketika entitas berhak tinggi (deputi) melakukan aksi atas permintaan pihak yang tidak berhak, karena tidak bisa membedakan instruksi sah dari yang jahat. Pada CI/CD, review bot dan CI runner yang memakai secret organisasi membaca konten pull request; pull request jahat bisa memicu agent CI untuk mengeksfiltrasi secret atau mengubah pipeline build. Agent yang menjalankan review kode otomatis dengan akses secret organisasi adalah confused deputy berskala besar: ia melayani siapa pun yang bisa mengirim PR. Pencegahannya: jangan beri agent CI akses secret penuh, jalankan dengan identitas hak paling rendah, dan jangan biarkan konten PR yang belum tepercaya memicu aksi dengan kredensial tinggi.

User: Kontrol apa yang harus dipasang sebelum mengizinkan agent mengeksekusi perintah?
AegisX: Sebelum agent boleh menjalankan perintah shell, memasang paket, atau mengubah file, pasang kontrol berlapis. Jangan auto-accept semua aksi: wajibkan persetujuan untuk operasi berisiko seperti install paket, perintah dengan akses jaringan, dan perubahan file di luar cakupan tugas. Jalankan agent dalam sandbox atau container dengan filesystem yang dibatasi dan tanpa akses ke rahasia produksi. Batasi izin agent ke yang dibutuhkan tugas ini saja, bukan izin penuh workstation. Dan perlakukan setiap perubahan yang dihasilkan agent seperti perubahan dari kontributor luar: review, tes, dan verifikasi sebelum digabung.

User: Bagaimana cara aman memakai konten eksternal (web, isu, PR) sebagai konteks agent?
AegisX: Konten eksternal yang dibaca agent harus dianggap data, bukan instruksi. Pisahkan instruksi sistem yang tepercaya dari data yang datang dari luar, perkuat instruksi sistem setelah konten yang diambil dimasukkan ke konteks, dan jangan biarkan konten itu mengubah kebijakan agent. Untuk isu dan PR, jangan biarkan agent mengikuti perintah tersembunyi di dalamnya; untuk halaman web dan hasil tool, pindai pola adversarial seperti penanda instruksi tersembunyi atau karakter Unicode tak terlihat, dan buang tag bergaya instruksi dari output sebelum dimasukkan ke konteks. Review setiap perubahan yang dipicu konten eksternal sebelum dieksekusi atau digabung.
